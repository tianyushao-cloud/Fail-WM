# b04/b06问题定位（2026-10-12）

使用相同codec34k和混合WM10k，未改权重。GT/codec/仅成功WM/混合WM四列视频已保存在本目录。额外真实历史交接视频在gt_handoff/，左GT、中原始开环、右真实历史交接后预测。该诊断允许模型获得中途真实图像，不能当作正常推理表现。

事实：
- g00006_b04属于early_release。新codec对整条GT重建无红方块漏检，位置均误差1.566px、最大4.636px。混合WM在t33确实画出落回桌面的方块，随后淡化，t41..45红色检测不到。给GT历史至t33、从t34接着生成后，t34初始保留落地方块，但t40已漂移，t44..45再次淡化/漏检。因此不能只描述成“没学会松手掉落”，还存在失败状态维持问题。
- g00014_b06属于skip_descend（跳过接近方块的下降阶段）。新codec整条GT重建无漏检，位置均误差0.401px、最大0.712px，能保持真实留桌状态。混合WM原开环t18开始把方块画到夹爪附近。补给GT历史到t16（夹爪已上抬，方块仍留桌），从t17接着生成，t17出现桌面方块与夹爪下红色伪影并存，t18仍把方块转移到夹爪。已目视t17/18/21。这表明单纯消除前段历史漂移不足以修正这个案例。

解释边界：这是2案例×1beam的诊断，不证明总体机制；生成是成对解码，不能直接把第一帧RGB等同latent单步因果错误。codec对GT重建正确不保证对WM产生的所有token组合都正确，但这两条GT目标本身能被当前codec表达。b03的改善不能外推为所有失败类型都已学会。

建议下一轮：固定现有codec与数据构成，优先修订E2事件/阶段采样，让成功和失败在抬升动作起点都得到监督（b06类型不能只靠迟到的grasp_attempt_failed事件），同时覆盖early_release结束后的稳定状态。成功阶段也用同样规则，保留均匀采样。仅从训练集构建schedule，不能把这两条val加入训练。E2单独对照通过后，再考虑方块区域loss加权或短程展开训练，避免一次改动多项。此次未启动/准备新的训练，两个原WM保持不变。
