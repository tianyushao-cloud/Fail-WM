### T01：清障后取物并复原

指令：把挡住红色目标物的蓝色物体移到暂存区，取出红色物体放到绿色区域，再将蓝色物体放回原位。

- 场景：1 个目标、1–2 个可移动挡物、暂存区、终点区。用窄槽/侧壁限制接近方向，让挡物实际占据夹爪的进入空间；仅视觉遮挡不足以形成操作依赖。
- 流程：抓挡物 → 暂存 → 取目标 → 放终点 → 恢复挡物 → 退爪并等待稳定。
- 成功：目标在终点并受正确支撑；挡物回到各自容差区域；所有物体已释放且稳定；要求暂存事件先于目标取出事件。指令明确要求清障、复原时才强制该顺序。
- 扰动：暂存位置过近、清障不足、目标抓取擦碰挡物、复原时撞走已放好的目标。
- 恢复：发现目标不可接近则再次清障；复原失误则重新摆正。恢复取实际状态，不回到初态。
- 初始难度：一个挡物；中等增加第二个挡物；困难收缩暂存空间并改变可行接近方向。
- 验证重点：排除从上方直接抓走目标的捷径，检查临时区、抓取位姿和机器人整体碰撞可行性。

### T02：长条物穿过狭窄通道后定向放置

指令：把带有方向标记的长条盒穿过通道，按标记方向放进另一侧的目标槽。

- 场景：长条刚体初始尺寸可从 12×3×3 cm 开始，程序化障碍形成有限高度通道。通道宽度必须同时容纳所需姿态下的物体和夹爪；宽度由真实碰撞几何标定。
- 流程：抓取 → 调整 yaw → 对齐入口 → 穿过通道 → 再转向 → 放槽 → 松爪。
- 成功：物体通过指定入口/出口形成的有向检查区域；最终完全落在目标容积内，有正确支撑、方向误差低于阈值、无夹爪支撑且稳定。
- 扰动：旋转过晚、入口偏移、通行高度错误、过早释放、恢复时继续向堵塞方向推。
- 恢复：停下 → 沿已通过路径退出 → 重新对齐 → 再通过。
- 难度：有效净空从宽到窄分级；角度容差可试 15°、10°、5°。这些角度和净空必须经试采校准。
- 验证重点：通道上方不能存在轻易绕开的路径；在允许擦碰的版本中，轻微接触不是自动失败，卡住/损坏保护条件另记。
- 对称性：普通长方体 yaw 具有 180° 等价性；按对称群计算误差。若指令要求唯一朝向，应增加可见方向标记或非对称几何。

### T03：两层堆叠并纠正偏心

指令：将大块放到基座目标上，再将小块叠到大块上方，保持稳定。

- 场景：两块不同尺寸刚体，初期下层 6 cm、上层 4 cm；后续降低下层尺寸、增加第三层。
- 流程：放下层 → 放上层 → 退爪 → 观察稳定 → 若歪斜/滑落则重放。
- 成功：下层在指定区域；上层由下层支撑而非直接落在台面；层间位置关系正确；不依靠夹爪或墙体；连续稳定至少 1 s。额外保留退爪后约 2 s 的观察尾段以记录延迟滑落。
- 扰动：横向偏心、下降过快、释放高度偏高、退爪碰到堆叠、摩擦改变。
- 恢复：拾起倒下的上层，必要时先矫正下层再重叠。
- 价值：区分“某一帧几何上叠住”和“持续稳定”，提供接触后的长期动力学结果。

### T04：先推后抓

指令：把侧面难以夹取的目标物沿台面推到开放区域，再抓起放到指定位置。

- 场景：目标位于侧壁或局部挡板附近；侧向推动通路开放，初始夹爪闭合所需空间不足。先验证该几何确实需要推动，且不把目标放到不可恢复的死角。
- 流程：以闭合夹爪/指侧接触 → 小步推动 → 观测实际滑移及旋转 → 必要时补推 → 换抓取姿态 → 放目标。
- 成功：发生持续物体-台面支撑下的推动与足够净位移；随后抓起并完成终点放置。若把推动规定为任务目标，指令及标签中显式体现。
- 扰动：推动方向偏斜、距离过长或过短、用初始位置执行后续抓取、不同摩擦下沿用同一动作。
- 恢复：重新估计实际位置，补推或重新对齐；落出台面则记不可恢复失败。
- 参数：可试 5–12 cm 推动距离，逐级改变摩擦及接触偏心；不得根据脚本是否进入 push 阶段直接认定成功推动。

### T05：装盘并搬运

指令：把两个小块放进托盘，再抓住托盘把它搬到另一处，两块都必须留在盘内。

- 场景：2 个内容物 + 带侧壁和单手可抓把手的程序化刚体托盘。初版使用凸几何组合和经验证的质量/重心，确保 Panda 夹爪能抓住把手。
- 流程：逐个装盘 → 抓把手 → 举起 → 平移/转向 → 落盘 → 松爪 → 稳定观察。
- 成功：托盘在目标区域并受台面支撑；两个物体均处于托盘内部且由托盘支撑；全部已释放并稳定；不能仅检查世界坐标接近。
- 扰动：装盘靠边、搬运急停、倾角过大、转向过快、不同内容物摩擦/质量。
- 恢复：内容物滑落到可达台面时先放稳托盘，再拾回内容物，重新搬运；恢复序列允许改变动作顺序。
- 难度：先一个内容物和高侧壁，再两个内容物、低侧壁与转弯。接触配对重点记录物体-托盘、托盘-夹爪及物体-台面。
- 价值：相近末端轨迹会因加速度、初始摆放、摩擦不同产生不同后果，适合动作条件世界模型。

### T06：抽屉取物后关抽屉

指令：打开指定抽屉，取出其中的目标物放到台面标记处，再关闭抽屉。

- 流程：抓把手 → 沿关节方向拉开 → 松把手 → 取目标 → 放台面 → 推/拉关抽屉 → 退爪。
- 成功：目标已离开抽屉且稳定放在台面目标；抽屉开度最终低于关闭阈值；物体取出前曾达到足够开度；关闭时无目标/夹爪夹在内部。
- 扰动：开度不足就伸手、拉动方向偏斜、抓错抽屉内物体、关抽屉前未清空夹持空间、关闭不到位。
- 恢复：重新开大再抓；从错误抓取恢复；检测阻挡后重新打开、清障、关闭。
- 复用依据：`vendor/robocasa/robocasa/environments/kitchen/atomic/kitchen_drawer.py` 中 `OpenDrawer`、`CloseDrawer` 提供关节交互参考；新建复合任务，不能将原子任务直接当完整链条。
- 约束：官方抽屉状态接口使用归一化开度，具体值须以 fixture API 为准；当前源码原子任务采用 open≥0.95、close≤0.05。复合任务的“足够取物开度”须由几何验证。

### T07：开柜收纳并关柜

指令：打开柜门，把长条盒放到指定层板内，退出夹爪并关闭柜门。

- 流程：开门 → 取盒 → 转向避开门板 → 放到内部层板 → 退出 → 关门。
- 成功：目标完全位于指定内部容积，受层板支撑；不伸入门体扫掠区；门处于关闭状态；手爪远离且物体稳定。
- 扰动：门开度不足、物体放得过浅、退出方向错误、关门顺序过早、门碰物体把它推出。
- 恢复：重新开门，重新抓取并放深，再关门。
- 资产与能力：需安装相应柜体/物体资产；先选所有关键抓取位姿均在固定底盘可达范围内的布局。需要移动底盘的布局作为独立升级，不默认为现有控制器可用。
- 价值：门最终关上并不代表任务成功；必须联合检查容纳、支撑、碰撞和关节状态。

### T08：两容器配套分拣与纠错

指令：把四个物体分到两个容器中，每个容器各放一个 A 类和一个 B 类物体，最后移开夹爪。

- 场景：2 个 A 类、2 个 B 类、2 个容器，后续增加外观相近的干扰物。初版可用不同形状/颜色的程序化物体原型；厨房语义版使用食品和餐盒资产。
- 流程：识别待装集合 → 依次抓放 → 核对两个容器内容 → 若错放则取回并纠正 → 退爪。
- 成功：每盒恰有一个 A 和一个 B；四个实例互不重复；无错误物体混入；内容物均在对应容器内并稳定。允许多种合法抓取顺序，不规定唯一脚本路径。
- 扰动：相似物体误抓、误投容器、搬运中掉落导致少装、错放后仍继续下一项。
- 恢复：从错误容器取回放错物体，或补齐缺失项；记录恢复是否破坏已有正确状态。
- 复用依据：`.../composite/packing_lunches/pack_identical_lunches.py` 的 `PackIdenticalLunches` 已检查每盒一种蔬菜加一种肉和实例唯一性；官方初始冰箱门已开，若增加开门步骤需改场景和判据。

## 3. 跨任务的数据设计

### 动作分支与扰动时刻

每个物理初态建议采 6 个分支：2 种合法参考策略、1 个轻扰动、1 个接近成功边界的扰动、1 个中后段扰动、1 个允许恢复的分支。配比是采样意图，不是成功/失败标签。

- 尤其保留“前 70% 做对、最后一个动作出错”的样本；新增任务不要只在第一次抓取时注入失败。
- 先扫描扰动幅度，找到能产生不同实际结局的范围。保留部分明显失败，同时增加接近成功边界的困难负例。
- 恢复触发来自真实事件和当前状态；始终保留恢复失败轨迹。
- 为严格比较动作分歧，可从同一前缀状态分出多个后续 rollout。每个 rollout 独立初始化一次，执行过程中不 reset、不瞬移、不绑定物体。
- 前缀分叉需保存/恢复完整 MuJoCo 积分状态、控制器目标/内部状态、夹爪内部积分、随机数状态、fixture 开关等 Python 逻辑状态、事件历史。仅保存 qpos/qvel 不足以保证相同起点。不能直接套用当前只面向简单初态的回放逻辑。
- 改质量/摩擦会改变物理模型；归为同一个父场景家族以防 split 泄漏，但不声称与原模型拥有完全相同动力学状态。

### 标签与成功判据

同时输出逐物体事件、子目标状态和最终结果：

- `object_ids`、`object_roles`、每物体 pose/velocity、fixture joint/state。
- `in(object, container)`、`supported_by(object, support)`、`grasped(object)`、`door_open`、`blocking` 等关系与任务谓词。
- `subgoal_reached` 与 `subgoal_valid_now` 分开：曾经把物体装进盘，之后掉出来，不能一直算已完成。
- 失败至少区分目标选择错误、前置条件不满足、碰撞阻塞、滑落/倒塌、目标区域错误、关节未到位、超时、不可恢复。
- 同时记录首次偏离任务约束的时刻和终局失败原因；不要根据扰动名称反推原因。
- 通用稳定条件初值可采用连续 1 s 内位置/姿态关系满足，线速度<0.03 m/s、角速度<0.2 rad/s，并且未被夹爪支撑；物体尺度不同需校准。离散电器状态另按状态机判定。
- 接触力只做诊断时可按 20 Hz 保存；要分析短暂碰撞/冲量时在物理子步聚合每控制周期接触峰值/冲量。20 Hz 末帧接触检查可能漏掉碰撞。

### 训练与评估边界

- 采用父场景分组：布局、物体实例组合、初态以及其全部扰动/恢复/共享前缀分支放在同一 split。
- 除随机初态测试，增加未见物体组合、未见几何净空/目标布局和未见任务组合测试。划分按泛化目标分别报告，不能把相同分支当独立场景。
- 任务语言、目标物体/区域需显式记录；颜色与任务角色随机置换，避免“红色永远是目标”。
- 用 simulator 真值控制可用于采数，但应标明 privileged scripted policy。真值事件和状态可作监督/评估，视觉模型推理时不提供未来标签、执行后的末端位姿或隐藏物理参数。
- 对相同画面但质量/摩擦不同的场景，早期结果可能不可从单帧确定；用历史观测/接触探测或分布预测，避免将不可辨识性误当模型错误。
- 评估至少包括最终成功、各子目标完成率、失败发生时刻、恢复率、长时滚动关系保持、碰撞/滑落预测，而非只看图像误差。

## 4. 代码改造清单

| 现有模块 | 必要改造 |
|---|---|
| `environment.py` | 用任务注册/独立子类管理任务；对象与目标映射；加入程序化容器/障碍或官方 fixture；逐任务 `_check_success` |
| `initial_state.py` | 从单个 cube 扩展到全部刚体/fixture；稳定初始化；可达性、碰撞及前置依赖检查 |
| `controller.py` / `batch_controller.py` | 复用移动/夹爪基础动作，新增旋转过通道、推、堆叠、搬盘、拉抽屉/开门；任务状态机按真实状态推进，允许恢复与超时 |
| `events.py` | 对象级事件 + 接触对 + 支撑/容纳关系 + 历史子目标 + 当前有效状态；校准各任务阈值 |
| `recording.py` | 多物体 `(T+1,N,7)` 位姿/速度、对象 ID 与模型参数、fixture 状态、任务关系；变长对象数提供 mask/索引；长轨迹用分块 HDF5 写入 |
| `batch_plan.py` | 任务、难度、初态家族、分支、扰动阶段和 split 统一生成；保留计划哈希 |
| `batch_validation.py` | 多物体/fixture 回放和标签重算；验证恢复后的控制器/环境逻辑状态；独立检查关系与稳定性 |
| `action_conversion.py` | 固定底盘阶段保持现有 raw12/target13 定义；若加入底盘/躯干动作，额外保存相应目标与模式，不能只用手臂 target13 表示完整动作 |

必须保留 `state[i], RGB[i], action[i] -> state[i+1], RGB[i+1]` 对齐、采样缓存同步与回放校验。新增 schema 版本，旧数据不要静默改成多物体格式。

当前 horizon=1500，即 20 Hz 下 75 s，但 `ignore_done=True`，不能依赖环境自动超时；长任务应设置并记录显式采集步数上限。当前 Recorder 把 RGB 累积在内存再转数组：90 s 的单视角原始 RGB 已约 1.66 GB，四进程及复制会显著放大内存。长轨迹先改分块写盘，再扩大并发。

相机初版保留当前第三人称，必要时增加已校准的腕部视角用于检查遮挡/放置；多视角会增加存储和渲染成本。先检查低处、抽屉内与通道出口是否在视野内，再决定采哪些视角。

## 5. 推荐试采顺序与验收

1. 先实现 T01、T02、T05：覆盖前置依赖、姿态约束、多体动力学。每任务 10 个父场景 × 6 分支 = 60 条，三任务共 180 条。
2. 先用少量确定可达场景调通参考控制；参考轨迹频繁失败时先区分布局不可行、控制器能力不足和任务本身难度，不能把实现错误当困难样本。
3. 检查每任务是否真实产生中后段失败和至少一种恢复；抽查成功、失败和恢复视频，并重算几何/接触判据。若只出现早期抓空，调整扰动时刻和技能可靠性。
4. 逐条验证时间对齐、数值、原生动作回放与终局判据；为每个新判据构造“位置像成功但仍被夹持/未受支撑/已滑落”的边界场景检查。
5. 验证通过后，每任务扩至 100 个父场景 × 6 分支，三任务 1800 条；分组划分在采集前固定。再加入 T03/T04 与安装资产后的 T06–T08。
6. 试采成功比例只作诊断，正式目标覆盖不同难度及真实结局。若另制失败占比较高的训练集，保留完整母集、选择规则和未经结果筛选的测试集。

## 6. 厨房语义拓展范围

官方 `ReheatMeal` 可以作为后续“容器搬运 → 关门 → 按启动键”的参考，源码路径为 `vendor/robocasa/robocasa/environments/kitchen/composite/microwaving_food/reheat_meal.py`。它初始化冰箱和微波炉门为打开，终局检查容器/食物位置、门关闭与 turned_on 状态。若要求完整开门链条或严格操作顺序，必须增加初始化与事件历史检查。

洗菜、加热、倒水等名称中的语义状态，不等于已仿真真实液体、清洁度或传热。当前第一阶段以可核实的刚体接触、容纳、关节和开关状态为目标；真实流体/切割/烹饪物理需要另行建模与验证。
