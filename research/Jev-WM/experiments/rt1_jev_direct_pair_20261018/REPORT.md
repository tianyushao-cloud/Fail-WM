# Jev 局部直接候选比较：2026-10-18

本轮共24次真实API请求：原方案6次基本检查，失败后18次输入/选项诊断。模型为gpt-6-luna，使用现有/v1/decisions接口。训练更新0步，未改变权重。

原计划144次：两个验证窗口各6个真实配对，4段×AB/BA；相同视频、GT/冻结、GT/黑屏控制；部分配对重复。基本检查已经失败，故未继续其余138次原计划。实际评估的是窗口2（open middle drawer）未来25–32帧，包含group0/group1、group0与自身、GT/黑屏三组，均做AB/BA。不能把结果写成两个窗口全部候选的完整评估。

## 结果

| 输入版本 | 相同视频 AB/BA 原始回答 | GT/黑屏 AB/BA 原始回答 | 真实group0/group1 AB/BA原始回答 |
|---|---|---|---|
| 三列逐帧图+32帧总览 | A / A | A / A | A / A |
| 去掉总览，仅8张三列图 | A / A | C / C | A / A |
| 同上，答案顺序倒置为D/C/B/A | A / A | C / C | A / A |
| 每时间点GT/A/B分开输入，语义选项 | candidate_B / candidate_B | candidate_A / candidate_B | candidate_B / candidate_B |

A/B代表当次请求标签。交换后继续选同一个标签，实际对应不同候选，不能视为一致偏好。语义选项为no_difference、insufficient、candidate_B、candidate_A；因此平局选项并未缺失，也不是只把第一个列出的选项当成答案。

所有4种版本的相同视频控制均未输出平局（原始答案0/8正确）。其中6次错误选择通过P≥0.60且第一二名差≥0.20的筛选，2次低置信度弃权。真实配对在4种版式中都发生物理赢家翻转，未产生可接受偏好。

分开输入图片+语义选项的GT/黑屏控制两次均正确，最大类别概率0.97/0.99。它改善了明显坏样本的判别，但未解决相同视频和真实候选的比较问题。该变体同时改变了图片组织、提示词、标签和选项顺序，不能据此分离具体成因。

## 输入审计

- 相同视频两路数组逐字节相同。
- GT/黑屏控制中，GT候选逐字节等于REFERENCE；另一候选全部为0。
- 每个目标时间戳的REFERENCE、A、B图像像素逐帧核对，AB/BA正确交换内容，没有镜像图像。
- 物理赢家映射函数已检查：AB选A与BA选B指向同一原候选。
- 所有API返回保留原始类别、概率和request id；没有把失败控制改写成平局。

实际输入例图见input_examples/index.html。probe.py、diagnose.py保留输入构建代码。diagnose.py中local_only/local_reverse_options使用基础prompt删除总览描述后的实际文本，修改规则在源码中；诊断identity里的prompt保留基础prompt。完整请求图片可由对应帧、源码和变体确定性重建。

## 结论与边界

这个版本不能直接用于RL奖励。最有力的证据是同一视频被判为不同质量，而不是某个真实预测被判错。现象与标签/角色/位置敏感相符，但本实验没有区分这些因素，也不能证明Jev在所有输入方式下均无效。

停止扩量是基于控制样本失败，不是缺少训练授权。当前仅验证了一个时间片上的比较机制，不是任务性能评估。两个既有验证窗口已用于裁判开发，不能作为最终盲测。

后续若继续纯Jev方向，应先在同一8帧片段上通过“相同视频必须平局、交换候选实际胜者不变”这两个最小检查，再扩展到RL。更换裁判或改用逐项可见事实判断都需要重新校准；不能仅放松置信度阈值来制造训练信号。
