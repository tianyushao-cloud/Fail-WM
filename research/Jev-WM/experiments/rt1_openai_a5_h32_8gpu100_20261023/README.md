# RT-1 Decisions：4卡第10步 → 8卡总100步

在可见8张CUDA卡的任务中执行：

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7 bash /media/tyshao/Jev-WM/experiments/rt1_openai_a5_h32_8gpu100_20261023/run_8gpu.sh all
```

从 `rt1_openai_a5_h32_20261021/train/checkpoints/step_000010` 继续，
总目标100步，即新增90步。模型、文本适配器和Adam动量不重置。
全局batch仍为16，8卡每卡2次梯度累计；每rank 1个CPU线程，
裁判每rank 2并发，总共16并发。训练计划顺序、学习率、奖励维度和校准不变。
阶段 `train` 只训练；`all` 还导出权重、评估固定第50/100步并生成报告。
`check` 离线核验；重复执行命令自动从最新完整检查点续训。

## 跨卡数状态迁移

原训练严格绑定配置、源码与卡数指纹。这里生成独立的、附迁移审计的
八卡第10步检查点，保留严格指纹校验，不修改原检查点。
四个已有rank的全部RNG状态保留，新增四个rank的独立RNG种子由来源检查点哈希确定。
`migration.json` 记录来源、权重哈希、Adam状态语义哈希、种子和配置差异。

新版本独立加载**原始RT-1 SFT参考模型**，避免deepcopy的文本hook仍绑定actor。
因此这属于保留第10步actor/Adam状态的续训，并非旧四卡有缺陷实现的逐位等价100步。
单卡暂停的两个实验和旧四卡目录不由此脚本启动、暂停或覆写。

## 断线等待

凭据自动从私有共享配置读取，不写进脚本或日志。沿用本机7897 → SSH反向隧道
→ 服务器私有认证桥接的路线。队列任务无需本机在线即可启动等待。
启动前验证完整的认证HTTPS通路；断线最多等待48小时。
训练中遇到连接错误、429、5xx，在本轮worker退出后退避30/60/120/240/300秒，
等通路恢复，再从最近完整检查点续训。连续无法推进超过48小时则安全退出，
已保存的检查点/真实API回执保留，再次运行同一命令即可继续。
401/403、模型/数据/评分格式/预算错误直接失败，不假造奖励。

每步原子提交完整checkpoint。`.partial` 不参与恢复；失败批次的未提交metrics
与半成品目录归档到 `train/recovery_archive`。已返回的同一请求评分从独立回执缓存复用。
本机休眠、关机或断网期间没有新评分，恢复网络/隧道后继续。
容器被队列系统终止、机器重启或任务时限到期，需要重新提交同一命令；脚本不能阻止平台回收。

新实验独立HTTP尝试上限120000（含重试），不重置旧实验预算。
每步约768个新请求，90步约69120个，不含失败重试；以实际缓存命中/评分协议为准。
完整100个检查点约需150GB磁盘空间，150GB RAM并不等于检查点磁盘预算。
