# Jev 分段裁判校准：2026-10-18

本轮完成 21 个案例、48 次真实 Decisions API 请求，模型为 gpt-6-luna。无训练更新，也未改动现有 SFT、R0 RL 权重与训练源代码。

输入为2帧初始观测、32帧REFERENCE、32帧PREDICTION。每8帧分别判断结构、动态、交互，并另报主要错误类型。接口返回分类和概率，不产生自由文本解释；页面里的错误类型是裁判判断，不是人工确认。

## 校准结果

- GT自身与匹配停顿对照：180/180 个分项通过。包含重复请求，并非180条独立视频。
- 人工冻结的后半段：12/12 个动态分项识别为错误。
- 后半段倒序：10/12 个动态分项识别为错误或部分正确；其余因低置信度未接受。
- 人工修改样本未修改的前半段：70/72 个分项正确，2项发生误判/弃权。
- 全部案例交换展示顺序：225/252 个原始分项一致（89.3%）。其中真实预测为91/108（84.3%）。
- 6个案例同顺序重复：72/72 个原始分项一致；其中3个为GT，3个为RL。
- 按原先“12项都确定才汇总轨迹reward”的保守规则，真实预测只有3/21次评分可用。该计数包含9个真实预测的双顺序请求与3个RL重复请求。

预先写下的可用reward比例门槛为50%，本轮为14.3%，因此校准未通过。其余预设门槛通过，但这不足以说明裁判适合训练。

## 具体现象

场景2 RL/ReCAP 的残留冻结在未来17–32帧被稳定判为动态/交互错误。场景1 RL/ReCAP 的运动和交互评分不稳定，同一段在换展示顺序后会从部分正确变为错误。场景3 RL/ReCAP 的评价较高，但动态“正确/部分正确”仍受展示顺序影响。

这些结果证明分项设计能提供比原先全平局更丰富的诊断；尚不能证明它能稳定排序细微差异的候选，更不能证明用它训练一定涨点。

## 不确定项的事后分析

为区分“裁判完全没信号”和“汇总过于严格”，另计算了分数范围。只保留跨展示顺序及已有重复请求均高置信度一致的分项；其他项枚举正确/部分正确/错误，不填0、不放宽阈值。保持原权重（结构0.2，动态0.4，交互0.4）和封顶规则。

真实预测108个分项中有80个（74.1%）具有上述一致性。对RL/ReCAP和两种SFT的6次场景内比较，只有场景3的RL/ReCAP相对SFT/全部历史范围严格分离。RL/ReCAP相对SFT/ReCAP的3次比较均有重叠，不能据此提供确定偏好。

范围是所选分类映射下的确定性上下界，不是统计置信区间。此分析为事后诊断，未替换预设门槛、未用于训练。

## 样本与限制

3个场景来自此前RL训练窗口。场景1和3取group0；场景2取group2，以覆盖已知残留冻结。每场景7种输入：GT、后16帧冻结、后16帧倒序、GT与预测均后半段停顿、SFT全部历史、SFT/ReCAP、RL/ReCAP。合成匹配停顿不是新采集的真实成功轨迹。

每种输入交换REFERENCE/PREDICTION展示先后；GT和RL额外同顺序重复一次。API按完整时间序列输入每帧PNG，页面视频固定左右并排方便人工查看；视频含2帧初始+32帧未来，以4fps展示。

## 下一步建议

优先改进局部时间定位：保留32帧总览，但对被评分的8帧提供同时间戳GT/预测对齐的局部证据，重新校准真实候选排序。当前整条轨迹只要一项不确定就弃权，会损失大量分项信息；后续可以研究只比较双方共有、可靠的时间段，但必须防止只保留容易的前半段而漏罚后半段错误。

在能够稳定排序同一起点的4个候选前，不应启动200步正式训练。下一轮应包含新的验证窗口，避免只针对这三个案例调提示词。

## 验证

已检查不确定项返回弃权、结构/交互封顶、缺失回答拒绝，以及3个场景全部合成控制的像素构造。导出时用ffprobe检查每个视频均34帧，并附全部文件SHA256。
