# Jev 奖励回执检查包

解压后双击 index.html。默认显示真实 SFT 候选，可切换新版/旧版控制样本。

## 这次的 0 分是什么

3组真实场景，每组4条不同的SFT预测视频，组成2对。6对×2种呈现顺序=12次裁判请求。
12次原始答案全部是C（无明显差异），P(C)范围 0.69–0.99。
本次真实候选没有被概率阈值改判成D；零奖励直接来自平局。
这是相对偏好奖励为0，不是视频质量或任务进展被评为0。两段同样好或同样差都可以是C。

## 内容

- 真实候选6对：全部收录，未按效果挑选。
- 新版控制9对：3组×相同/GT对黑屏/GT对冻结。
- 旧版控制9对：3组×相同/GT对黑屏/GT对冻结，保留此前失败证据。旧版为逐时刻交错输入，新版为整段按时间呈现；提示词也有差异，不能当作同协议重复实验。
- 每对有三栏同步MP4、首/中/末帧联系表、两个顺序的原始回执、任务和提示词。
- assets/包含原始uint8数组NPZ、无损PNG和原始请求元数据，可复原裁判所见的像素。
- scoring/包含实际奖励解析代码与诊断记录。

## 查看方法

先播放三栏对照，再暂停，用逐帧滑块查看细节。单击图片可打开无损PNG。
“交换A/B”会同时交换候选显示、选项概率和原始回执，避免把标签与实际视频身份混淆。
MP4以4fps展示12帧（2帧初始+10帧未来）；这是便于检查的播放速度，不是原视频采集帧率。
MP4有视频压缩；人工精细比较应看无损PNG。裁判实际收到的是多张原始PNG图片和文字标签，不是三栏拼接视频。

## 奖励映射

原始返回A/B/C/D及选项概率，不包含文字解释或推理过程。包中“归零原因”只解释代码映射，不能当作模型给出的理由。
最高选项概率至少0.60，且领先第二项至少0.20，否则程序将该次结果视为D。
两个顺序映射回同一候选都获胜，才给+1/-1；C、D或顺序不一致均不产生该对的偏好奖励。
confidence仅展示，不参与奖励；它不是已校准的正确率。

当前包是裁判诊断材料，未进行RL参数更新，不能据此宣称优于或劣于SFT。
