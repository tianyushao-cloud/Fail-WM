# 纯 Decisions 奖励：进一步排查与可执行的改进

本轮完成三条路径的实测，以及一个新的可靠候选对奖励实现。找到局部有效的训练信号，但尚未达到固定校准门槛；没有启动新的 RL，没有新权重，不能声称涨点。

## 主要发现

1. **不是继续改一句提示词就能消除顺序偏差。**
   单时刻、单候选、对称 A/B 比较、图片内烧入标签仍有偏差。真实候选物体分最大 AB/BA 差为 0.2925，黑图几何分从 0.0025 变为 0.16。共21次真实 API 请求（同图交换请求完全相同，缓存去重）。
2. **单图事实识别降低了角色绑定复杂度，但小物体仍对输入尺度敏感。**
   人造复制/移除方块在384和640两种大小都识别正确；真实 candidate_1 的第10帧存在额外方块，其 extra_cube 分却由0.18变为0.98。可见性和夹爪接触判断也不完全稳定。这24次请求仅作诊断，没有把该分数接到奖励中。单帧数方块本身无法防止冻结运动。
3. **整组排序失败不意味着组内每一个偏好都无效。**
   新代码按每个候选对筛选，允许不稳定的第三个候选退出，而保留两种顺序均支持的可靠偏好。没有降低原综合分差0.04和顺序差0.15门槛，并新增组件级检查及物体分底线。

## 实现

新增 src/futureworlds/reliable_pair.py、scripts/reliable_pair_decisions.py、tests/test_reliable_pair.py、docs/RELIABLE_PAIR_DECISIONS.md。
training.py 只增加一个奖励分派分支；decision_reward.py 增加 rubric 校验值。原训练目标、候选生成、KL实现和 vendor 未改。

对每个候选获得参考先/预测先两组官方 Decisions 分数，筛选：
- 两种顺序下综合差与物体差均至少0.04。
- 胜者几何/场景分均不低于败者；不存在用好背景补偿坏物体的取舍。
- 入选两条候选的每一个分量顺序差均 <=0.15。
- 胜者两顺序物体分均 >=0.50，避免全坏候选被强制选优。
- 多个合格对取最小跨顺序优势最大的一个；精确并列则弃权。
- 胜者+1，败者-1，其他0；组均值为0，其他候选的GRPO偏好advantage严格为0。KL继续作用。
- 整批无有效对仍停止，不伪造更新。

全部训练标签来自 Decisions。LPIPS/MAE/颜色检测没有进入奖励。颜色阈值仅用于参考确定的统一局部视图；不是物体行为真值。该方法是新的纯Decisions实验，不是声称严格复现论文的原始奖励。

开始生成候选前固定 protocol.json，使用之前预选但尚未评过的3个训练集初始场景；没有用验证集/测试集挑提示词。使用同一成功SFT和codec、原始首两帧、32帧候选、原MemSPO生成设置。

旧6组开发记录回放保留2组可靠对，其中g00053原先因候选3不稳定整组弃用，现在可保留0>2。旧组只作开发证据，不算独立验证。

## 接下来怎么做更有价值

可保留这套“只学习可靠对”的实现，作为后续训练入口。当前瓶颈仍是可靠偏好覆盖率，而非训练步数。
下一轮需要预先固定更大的一批初始场景，测量可用候选对的比例与语义正确率；必要时单独实验增加候选多样性，避免四条几乎相同的轨迹让裁判硬分高下。这将是偏离原候选配置的新实验，需要明确记录。
如果坚持纯Decisions，当前不能承诺同时提高LPIPS和行为正确性；不宜把未过校准的分数直接用于长训。
